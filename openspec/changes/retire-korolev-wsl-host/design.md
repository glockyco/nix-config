## Goals / Non-Goals

**Goals:** One supported environment per owner machine; no Windows-to-WSL repo/hook/tool fallback; lossless migration before destructive retirement; keep Mac Nix and native Windows owners distinct while sharing user facts; portable strict OpenSpec acceptance independent of the deleted flake input.

**Non-Goals:** Project toolchain implementation, employer share/Intune policy changes, repository determination of employer Docker licensing, Mac Nix removal, desktop reprovisioning, WSL feature disablement, Docker-owned distribution removal, OMP transcript conversion, credential/private-key/browser-profile transfer, machine-wide convenience services, or publication/activation authorization implied by a plan.

## Decisions

### 1. Cut over the actual host, not every Linux CI tool

Remove `hosts/korolev/`, `modules/nixos/`, the whole WSL role, NixOS configuration construction and obsolete role/kind branches. Nix manages only macbook-pro. Keep `aarch64-darwin` host output discovery; declare `x86_64-linux` explicitly as a CI-only flake system so existing generic Linux formatting, package behavior, DNS, secret and policy checks remain useful. Its shell is for CI, not a supported Korolev or third owner workstation. The Linux job no longer resolves a host's Nix package; it uses the same reviewed/pinned Determinate CI installer already used by the workflow. Windows remains outside Nix's system registry and uses its native development bootstrap.

Remove WSL-only source packages/checks and dead registrations, not just hide them behind `optionalAttrs`. Narrow platform fixtures to Mac and Windows; retain synthetic negative policy/type fixtures where they test a durable invariant. Delete Linux-only user package consumers with the retired modules, but retain `modules/shared/user-packages.nix` and all Mac-required packages. No shim `nixosConfigurations.korolev`, retired `open`, dormant role, or WSL launcher remains.

Spec synchronization uses explicit retirement plus accurately named successor requirements where removing obsolete scenarios changes the contract, rather than dropping current scenario headings from a MODIFIED block: `Declared access policy` → `Declared native fleet access policy`; `Tailnet SSH access to the Darwin host` → `Native user SSH access to the Darwin host`; `Host gates generated per host` → `Managed Nix host gates`; `Peer facts come from the registry` → `Declared managed-host and native-peer facts`. Each REMOVED block names its ADDED successor and preserves the complete applicable scenario set without retaining active Linux-host/builder acceptance.

**Alternative rejected:** Remove every Linux check because no Linux host remains. Generic CI checks still exercise cross-platform packages/policy/formatting and satisfy meaningful existing Linux protection; retaining them explicitly is clearer than keeping a phantom host. Keeping WSL "for Nix" contradicts the final owner decision.

### 2. Preserve native network access; revoke only builder-only access

Korolev's Windows node/tag/listener established by C3 remain. Move its durable policy membership from `fleet.hosts` to `modules/shared/tailnet-peers.nix`, preserving reachable native SSH and existing source keys. Mac SSH continues with a regular root-owned authorized-keys file, key-only authentication, tailnet-only bind and no forwarding/tunnels. Remove `korolev-builder`, root daemon-client settings/pin and `tailnet-builder-check`. Remove Darwin's non-root `trusted-users` entry that exists solely for remote imported builder paths; ordinary native Windows user SSH does not grant Nix trust and owner-authorized sudo still works. Keep root trust and any independently justified local Nix settings. Tests must distinguish ordinary native command status from the deleted remote build proof.

No WSL private key is copied to Windows. C3's separately generated/enrolled Windows key replaces user access; retire any remaining WSL user authorization only after the Windows endpoint is accepted, without deleting unrelated keys. Keep Windows `macbook-pro-known-hosts.tmpl` and Mac server identity; delete only Linux builder-known-hosts ownership. Archive backup retains old private material; live Mac authorization must no longer accept the retired builder key.

**Alternative rejected:** Delete all Korolev policy/SSH entries along with the host directory. That would remove the accepted Windows machine. Preserve root builder as a convenience: obsolete credential exposure and no Linux caller.

### 3. Native project owners replace WSL behavior

Windows containers use nix-config's native `Docker.DockerDesktop` document resource, installed in machine scope as the third explicit exception alongside Zen and Tailscale. The resource is self-updating: no version pin, latest available initial installation, acceptance of a newer installed release and no downgrade/reinstall merely because WinGet lags. SCCH Intune's update-only package keeps the installation current; it is not an initial installer or competing repository pin. Remove Docker from `windows/managed-applications.json` with the dated log evidence and Git precedent. Update `windows/configuration.winget`, `windows/tests/native-contract.ps1` exception/policy invariants and app/installer fixtures; preserve the two existing Administrator scripts' narrow Zen/Neo ownership. Standard-user apply remains unelevated except the approved installer UAC prompt, whose credentials are owner-typed.

Before installation, the owner/employer must confirm Docker Desktop licensing/subscription entitlement: paid subscriptions are required in larger organizations. Intune's update package indicates IT already uses Docker Desktop, but is not proof of this user's entitlement. Record confirmation or a precise blocker in the Korolev runbook rather than deciding employer licensing in repository configuration. Then perform the separately authorized live installation and bounded native Docker/Compose smoke before project migration; inspect engine/context and stop resources started by verification. Repository-declared install or readiness failure blocks migration and never selects a WSL-host fallback. Mac retains Nix Docker client/Compose plus user-controlled Colima. `test-generalization` owns its Docker toolchain image, not workstation Nix or this change.

SCCH data uses employer-managed `S:\` or `\\scch.at\SCCH`. Each project declares/configures its share root rather than inheriting `/mnt/s`. Native HTTPS Git uses the accepted per-user Git/GCM with Windows-local login; Mac Git remains supported. Reference C3's official per-user TeX Live (bundled Perl/latexmk/biber, tlmgr updates, yearly reinstall), official TexLab release and native Poppler/QPDF/ImageMagick/Pandoc. Do not add second installers or re-plan those pins here. Personal projects require Mac and Windows acceptance; SCCH work projects require only Korolev acceptance. Neither statement requires migrating reference clones.

**Alternative rejected:** WSL path aliases or broad compatibility wrappers. They hide unported project assumptions and would keep the retired environment as a runtime dependency.

### 4. Portable OpenSpec is the cutover dependency, not a new private checker

In `lefthook.yml` add platform-appropriate direct commands using the host's actual `openspec` (Mac Nix package; Windows C3's exact npm pin). Every local invocation first proves `openspec validate --help` advertises `--archived`, failing clearly if not; then runs both `openspec validate --all --strict --no-interactive` and `openspec validate --archived --strict --no-interactive`. Fail on either nonzero status; no archived opt-out, pinned-package installation at commit time or WSL delegation. The existing platform hook dispatch remains, but staged `.nix` on Windows unconditionally fails with guidance to commit Nix changes from the Mac and run the reviewed Nix gates there/CI; it cannot skip or delegate even if `wsl.exe` happens to exist. Other native formatting/schema/parser/ownership checks remain.

CI calls `glockyco/omp-agent-setup/.github/workflows/openspec.yml` at a reviewed full release commit SHA from `support-native-windows`, with `openspec-root: '.'`. That workflow owns its exact CLI pin and validates the caller revision, including explicit `--archived` support and both strict commands. There is no invented SHA in this draft: selecting the released SHA is a concrete implementation task. nix-config does not pass CLI versions/flags or duplicate generator logic. After local and CI acceptance, remove `personal-omp-plugin` plus `openspecContracts`/`openspecAdapters` and orphan lock nodes. omp-agent-setup retains its `lib.openspecCheck` until consumers migrate; its own CI owns adapter freshness. Require the new OpenSpec job alongside Darwin, Linux-generic, Windows and live-policy jobs; update policy deploy's workflow-completion checks and branch protection under owner authorization, not a generic main-success claim.

**Alternative rejected:** Keep the Nix input solely for OpenSpec, copy its implementation, install unpinned OpenSpec in hooks, or silently tolerate unsupported archived validation. All would preserve the dependency or weaken consumer contracts.

### 6. Retire only after project acceptance and a retained export

Track per-project native acceptance and, for personal projects, Mac compatibility evidence; a general tool smoke cannot replace each project's acceptance. After all WSL sessions finish and every preservation decision is resolved, coordinate with the owner to stop the `NixOS` workload, export `wsl --export NixOS <backup>.tar` to an owner-selected retained location outside the checkout, and record path, success and readable archive/integrity evidence. Export is a credential-bearing whole-system backup: retain privately, never commit or publish it. Only then, with explicit destructive-operation approval, `wsl --unregister NixOS`. Verify `NixOS` is absent without changing Docker Desktop engine distributions, service or volumes.

Nix config removal and Mac activation are separately reviewed; keep recoverable source/user-file revisions until acceptance. If rejected before unregister, continue using the preserved WSL environment while repairing the native project, without pretending the final plan retains it. After unregister, recovery is an explicit owner-assisted import from the retained export into an approved distribution name and paths, not a command that reconstructs old sessions from Windows history. Recovery does not undo independent Windows credential/tool/Tailscale changes or the Mac's approved key revocation. No automatic re-enrollment, credential transfer or rollback activation.

## Risks / Trade-offs

- [Pending or untracked project data can be lost.] → Inventory actual state, let the owner decide content, preserve nested clones/untracked directories and ephemeral `/tmp` data before export; no reset or forced cleanup.
- [Path-dependent OMP bank identity can silently change.] → Calculate both banks with actual platform Bun/path resolution, preserve exact stable native paths and verify decisions in a fresh session; never copy queue/state.
- [Live and CI OpenSpec CLI versions can differ.] → Document Mac Nix and Windows npm pin provenance, require `--archived` support explicitly, run both commands and review reusable-workflow SHA upgrades; do not silently downgrade validation.
- [Removing a Nix host can drop Windows policy membership or generic Linux checks.] → Separate durable Windows peer facts and CI-only systems from managed Nix hosts, assert no duplicate Korolev identity and no retired output/gate.
- [Native tooling/project acceptance may reveal unsupported behavior.] → Block that project's migration/retirement gate and resolve in its owner repository; no WSL fallback or narrowed acceptance.
- [Mac authorization cleanup can revoke valid native access.] → Identify builder/user key fingerprints and provenance, remove only retired entries after native SSH proof; keep host pin and standard account/sudo boundary.
- [The export contains credentials and may be incomplete if sessions write during export.] → Finish sessions and quiesce the workload, retain privately with recorded integrity/readability evidence before destructive unregister.
- [Docker entitlement or initial installation is unconfirmed.] → Confirm licensing with the owner/employer before installation, then prove owner-assisted UAC installation and native Docker/Compose readiness before migrating container projects; an Intune update package is neither an installer nor entitlement evidence.
