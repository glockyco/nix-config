# Proposal

## Why

The approved fleet direction assigns packages and system settings to each platform and user files to chezmoi, including the future native Windows workstation. Removing Home Manager after the upstream OMP/Tern cutover establishes one portable user-file owner without making Windows depend on Nix evaluation.

## What Changes

- **BREAKING** Remove Home Manager from nix-darwin and NixOS/WSL, its module tree, state version, integration inputs and output consumers. Move all surviving user packages to `users.users.<name>.packages` and shell plugins to platform `programs.*` modules.
- Add `home/` as the chezmoi source root through `.chezmoiroot`, with per-machine configuration generated by `.chezmoi.toml.tmpl` and shared TOML facts read by Nix using `builtins.fromTOML`.
- Make chezmoi the owner of shell/Git/SSH/app configuration, themes and user setup; preserve tty-guarded fzf integration, mutable app state and every surviving Home Manager inventory responsibility.
- Adopt Zed and Karabiner through `modify_` files; call existing Mac helper packages from `run_onchange_` scripts. Keep screenshot location, Air launchd agent, power settings and Rosetta in nix-darwin.
- **BREAKING** Replace SOPS user secrets with chezmoi built-in age ciphertext and `private_` destination files. Reuse the Mac's existing age identity and re-encrypt only on the Mac; decrypted files persist across reboot.
- Run system switch followed by user `chezmoi apply`; render the real source in isolated flake checks instead of reading Home Manager output. Provide per-host cutover and two-part rollback and update README, AGENTS.md and operations guidance.

## Capabilities

### New Capabilities

- `user-configuration`: Single-owner chezmoi files/setup, shared machine facts, app-owned file adoption, encrypted secrets and explicit apply/recovery boundaries.

### Modified Capabilities

- `personal-omp-workstation`: Replace the shared Home Manager module-set requirement with portable system packages and shared chezmoi source; upstream OMP remains independently owned.
- `darwin-host-activation`: Split system activation from user setup, preserve helper idempotence/error behavior, replace Home Manager dry runs with chezmoi dry runs.
- `darwin-gui-environment`: Keep persistent GUI Nix lookup independent of interactive chezmoi shell initialization.
- `darwin-dependency-builds`: Retain keyboard and build-plan invariants when helpers/resources move to system ownership.
- `wsl-host`: Change the owned declarative configuration, defaults and Git identity requirements to system packages plus chezmoi.
- `batch-ssh`: Render and validate platform-neutral interactive/batch endpoints from chezmoi, retaining stdin, host verification and status propagation.
- `container-runtime`: Move Colima profile delivery to chezmoi and shared facts; WSL container runtime contract remains unchanged.
- `python-project-tooling`: Install `uv` in the system-declared user package set.
- `repository-quality-gates`: Replace Home Manager facts/output assertions and SOPS scalar checks while retaining typed registry, one package set, role boundaries and behavior tests.

## Impact

`adopt-upstream-omp-and-tern` is implemented and activated on both hosts; its remaining acceptance/archive gates belong to the integrator. The owner authorized this dedicated implementation worktree. Wrapper, updater and `modules/home/omp.nix` are gone; OpenSpec, Plannotator and language servers are ordinary Home Manager packages to migrate here. Ghostty (Mac) and Herdr (both hosts) remain installed secondary tools. Chez owns the Mac Ghostty settings/theme, Nix owns Herdr's user package, and the owner installs Herdr's OMP integration on demand; neither activation nor chezmoi touches `~/.omp`. This change owns neither OMP installation/plugin manager behavior nor native Windows provisioning nor WSL scope reduction. It keeps WSL GCM/GnuPG/pass until change 4 and retains the separately rendered Windows layer until change 3.

Implementation affects `home/`, `.chezmoiroot`, host/fleet/platform/role modules, helper packages, flake inputs/lock, flake checks, secret checks and consumers, and README/AGENTS.md/operations docs. Secret conversion and live Mac switch need owner participation; publication/merges require explicit authorization. No implementation or live state is changed by these planning artifacts.
