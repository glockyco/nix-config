# Design

## Context

See `proposal.md` for motivation. This is change 2 of the owner-approved fleet migration, applied only after `adopt-upstream-omp-and-tern` is archived. Repository files inspected for planning still show the old wrapper/Home Manager architecture; references to those files below are evidence for responsibilities, not instructions to recreate change 1's removed code.

Evidence: `modules/home/default.nix`, every `modules/home/darwin/*.nix`, `modules/roles/darwin/{desktop,air-client,container-client}`, `modules/roles/nixos/wsl-workstation/default.nix`, host declarations, `modules/fleet/`, `flake.nix`, `flake-modules/`, and the three Home Manager-dependent config checks. `README.md` Activate/Develop/Recover and `docs/operations/{dependency-updates,wsl-omp-bootstrap,container-runtime}.md` define existing release and authority boundaries. `.sops.yaml` and the three encrypted YAML files were read without decryption: one Mac recipient and three `token` values. `modules/home/darwin/secrets.nix` defines the identity path and consumer contracts.

The authoritative pre-planning evidence verified pinned platform options and chezmoi 2.70.3 support for TOML, `.chezmoiroot`, modify scripts, change scripts, built-in age and private files. Relevant upstream references: [chezmoi source attributes](https://www.chezmoi.io/reference/source-state-attributes/), [configuration template](https://www.chezmoi.io/reference/special-files/chezmoi-format-tmpl/), [scripts](https://www.chezmoi.io/user-guide/use-scripts-to-perform-actions/), and [encryption](https://www.chezmoi.io/user-guide/encryption/age/).

## Goals / Non-Goals

**Goals:** One owner for every surviving inventory responsibility; Nix remains the package/system owner; chezmoi alone writes user destinations; shared facts are single-source; all existing effective assertions survive; live cutover is reversible without exporting secrets.

**Non-Goals:** Install/update upstream OMP or its plugin; change Tern behavior; implement native Windows provisioning; remove WSL tools assigned to change 4; change tailnet topology, builder keys, project SDKs, browser state or Colima lifecycle. No Home Manager compatibility module, dual file ownership or new scheduler survives.

## Decisions

### 1. One source tree, local configuration, and shared typed facts

Root `.chezmoiroot` contains `home`. `home/.chezmoi.toml.tmpl` writes each machine's `sourceDir` to its actual checkout (not a cloned second copy) and persists `data.host`. Initialize with `chezmoi init --source "$checkout"`; do not pass `--apply` at cutover so the user can inspect the diff first. Read host selection once at init and validate against declared data; never infer it from WSL's unreliable pre-activation hostname. `chezmoi apply` subsequently uses this local config. Target home is outside source root, as the pinned-version evidence requires.

Verified init-template detail: with `.chezmoiroot=home`, `.chezmoi.sourceDir` during config generation is the effective `checkout/home`, so persist the checkout with `sourceDir = {{ .chezmoi.sourceDir | dir | quote }}`. The config template runs before automatic `.chezmoidata` loading; validate host selection using `{{ $facts := include ".chezmoidata/hosts.toml" | fromToml }}` instead of assuming `.hosts` is already present. This follows the [configuration template reference](https://www.chezmoi.io/reference/special-files/chezmoi-format-tmpl/), and a second pinned-version spike verified init, subsequent apply without `--source`, shared-data rendering and verify all exit 0. Both temporary init HOME/source trees were deleted.

`home/.chezmoidata/hosts.toml` owns facts used by both Nix and templates: Git identity, platform user/home and checkout paths, screenshot path, Darwin app records used by PATH/defaults, Colima capacities/mounts, and host role selection booleans needed by templates. Shared portable defaults/theme palette/SSH policy live in focused `.chezmoidata/*.toml` files. Use `hosts.macbook-pro` and `hosts.korolev`; platform-specific user/home/path facts are nested under `platforms.darwin`, `platforms.linux`, and, in change 3, `platforms.windows`. Windows and WSL may both set `data.host=korolev` without confusing `user` with `JGlock`.

Nix reads those files with `builtins.fromTOML (builtins.readFile ...)` in the standalone host declarations and validates their values through existing `modules/fleet/host.nix` types. Retain the directory-keyed name, system/kind, builder and tailnet facts, typed `config.host`/`config.fleet.hosts`, and explicit host role imports. Add an assertion that imports and shared role selections agree, rather than treating a rendered file/package as a role detector. Chez templates branch on `.chezmoi.os` and selected host/platform data only when necessary. Nix checks assert the same parsed TOML values, not repeated literals. Purely system facts remain in Nix; purely user config remains in chezmoi. A derived value has one computation owner: e.g. Colima architecture is computed from Nix's `hostPlatform.qemuArch`, not repeated in TOML.

Rejected: independently maintained Nix and TOML identities (drift), generated entire chezmoi source from Nix (Windows cannot use it natively), moving all system facts to a second generic registry (unneeded churn), per-host forks of portable templates.

### 2. System packages and platform shell integration

Every surviving Home Manager package is placed in `users.users.${host.username}.packages` using the flake's existing overlay-extended package set. This supersedes inventory suggestions of `environment.systemPackages`. Keep existing genuinely root/system packages such as Git needed by `darwin-rebuild`; do not move them out of system scope. There is no user `nix profile` bootstrap and chezmoi does not install ordinary Nix packages.

Portable package list: Git, Git LFS, delta, gh, ghq, uv, fzf, zoxide, ripgrep, fd, bat, eza, Starship, Typst, tinymist, TeX Live full, texlab, poppler-utils, Python with Pygments, aspell/English dictionary, chezmoi and the surviving change-1 OpenSpec/Plannotator/language tools. Mac additionally has Roslyn, OpenSSH with FIDO2, Fastmail wrapper, Mac helpers, Colima/Docker/Compose runtime check and Air tooling when its role is selected. WSL retains wsl-open, Linux GCM, GnuPG and pass until change 4. Deduplicate texlab appearing in two prior package responsibilities; one package derivation, not two owners.

Platform modules own zsh enablement/completion/autosuggestions/syntax highlighting, direnv+nix-direnv, and nix-index integration. Import `nix-index-database.darwinModules.nix-index` or `nixosModules.nix-index`. Keep login shell registration and NixOS GPG agent in system scope. The user `.zshrc` owns history behavior (100000 entries, sharing/append, ignore-all-dups and leading-space exclusion), prompt, zoxide, aliases/options, and fzf commands. It loads fzf only after completion and only inside `if [[ -t 0 ]]; then ... fi`; disable platform fzf history/integration options, including nix-darwin `enableFzfHistory`. Never source shell plugins twice. Preserve Starship Catppuccin powerline segments, directory truncation 5 and disabled command duration.

Mac `.zshrc` restores `/etc/profiles/per-user/<user>/bin` ahead of Homebrew after `/etc/zshrc` initialization, then adds the host-declared Tern bundle executable path. `.zshenv` owns EDITOR and Colima environment without sourcing interactive plugins. Preserve gh SSH default on Mac and HTTPS on WSL. Render Git LFS filters, delta wiring, `main`, rebase, automatic upstream push, `autocrlf=input`, ghq root and identity/includes. Do not own gh `hosts.yml`, SSH private keys, shell history, OMP state or Tern settings.

Rejected: system fzf integration (reintroduces the observed non-tty zle warning in `modules/home/cli.nix`), package installation through chezmoi (competing owner), keeping HM solely for shell hooks.

### 3. Nix-built resources, chezmoi destinations and Mac setup

Keep official Neo fixed-output resources in `packages/neo-keyboard-layouts` and upstream Karabiner rules pinned by `flake.lock`. Platform/role modules produce a read-only `/etc/chezmoi-resources/` resource set: manifest with package/resource identities and derived architecture, Neo source bundle location, normalized selected Karabiner rules, and FileTypes/default-app bindings. This is system build output, not a user-file owner. Chez templates read the resource manifest; the check harness substitutes an equivalent fixture manifest path in isolated configuration data. Runtime does not discover arbitrary store paths or fetch moving upstream sources.

Move the FileTypes bundle/declaration logic out of the obsolete HM module into the role's Nix resource declaration. Render its user destination from shared facts. Keep the full extension/UTI/scheme bindings and their intentional exclusions. `run_onchange_` scripts call `neo-keyboard-layout-install`, `default-applications`, `symbolic-hotkeys` and `apple-terminal-font` by installed executable name. Their rendered script includes the relevant manifest identities/declaration hashes, so a helper or pinned resource update reruns the appropriate step. Keep screenshot location in the already-existing `system.defaults.screencapture.location`; a chezmoi change script prepares its directory. Power/Rosetta and GUI launchctl PATH stay system-owned.

Zed and Karabiner use `modify_` templates, not replacement symlinks. Preserve undeclared keys/profiles and writable UI state, while reapplying declared keys. Karabiner merges managed Neo2 rules into the declared profile and preserves unrelated profiles and unrelated rules; do not append duplicate rules on repeated apply. Directory/file remain 0700/0600. Zed preserves its non-OMP settings, LaTeX extension and theme; use JSONC-capable parsing because Zed settings may contain comments. A parse failure stops without rewriting. Refactor the existing tested `karabiner-configuration` helper to support the stdin-to-stdout modify filter, retaining its error/private-mode assertions where applicable; remove its old whole-destination replacement path after all callers migrate. The modify template is the destination owner, not a second helper-side install. Keep modify filters pure and tested. Thin run scripts may invoke packages; reusable repository-owned logic stays packaged with behavior tests.

Air role remains temporary: Nix owns `launchd.user.agents.mount-air-share` with Aqua context, RunAtLoad/60-second interval, offline no-op, Tailscale/jq/osascript helper and log paths. Chez owns the `~/Air` out-of-store destination symlink. Convert the inline mount helper to a package with tests, removing the old HM launchd agent during cutover so two mounts cannot race. No Air fact enters the durable host registry; role-local facts are exposed in shared role data and removed together under issue #17.

Explicit Catppuccin Mocha/Mauve user config replaces the HM theming input: bat theme assets, delta config, eza colors, fzf colors/options, zsh highlight styles and Zed theme/extension. Preserve the actual generated theme values and source licenses at implementation, compare against the pre-cutover fixture, and remove `catppuccin` once no consumer remains. Ghostty theme/config is already gone.

Rejected: `.chezmoiexternal` duplicating keyboard pins (two pin owners), store-symlinked app-owned JSON (writes break), whole-file overwrite of UI settings (loses state), treating `run_onchange_` as ongoing drift detection (it reruns only when source hash changes). Helpers still compare before write when rerun; explicit verification/recovery can rerun a selected setup script when external preferences drift.

### 4. Secrets use built-in age, with plaintext retained only on the Mac

Use `encryption="age"`, `useBuiltinAge="on"`, the existing `~/.config/sops/age/keys.txt` as identity, and the public recipient already in `.sops.yaml`. Chez source names use both encryption and `private_` attributes; decrypted destinations are `~/.config/credentials/fastmail-token`, `cloudflare-dns-token` and `cloudflare-workers-token`, all 0600 under a 0700 directory. Mac-only source selection ignores these paths on Linux/Windows; those hosts have no Mac recipient/identity configuration. Future hosts receive their own keys only through a separately authorized enrollment.

During implementation on the Mac, use a user terminal with tracing disabled and `umask 077`. Pipe `sops --decrypt --extract '["token"]' secrets/<file>.yaml` directly into chezmoi's built-in age encryption with explicit public recipient, writing ciphertext to its `encrypted_private_` source path. Verify CLI stdin/output flags using `chezmoi encrypt --help` and a disposable non-secret fixture before conversion. No plaintext output, transcript, repository temporary file, Nix evaluation, derivation or remote terminal capture is permitted. An owner-assisted local run can compare decrypted replacement to the existing consumer value entirely in local memory and report equality only. Keep original ciphertext until the Mac decrypts all replacements, private modes and consumer checks pass. Remove `secrets/`, `.sops.yaml`, sops-nix input/module/launch agent and SOPS-only fixtures only after acceptance; do not create a persistent dual secret path fallback.

Update Fastmail's package wrapper and both direnv helper paths together; preserve project opt-in and separate DNS/Workers scope. README DNS commands must use the new path without printing values. `chezmoi verify` is local because rendering secrets decrypts them; CI uses disposable generated identities/ciphertexts and never production credentials. Repository secret validation tracks the encrypted source inventory, rejects missing/renamed/unattributed secrets and malformed/plaintext age payloads, and tests both armored/binary formats supported by the selected encoding. A format check cannot prove recipient validity; synthetic decryption tests and Mac live verification provide that proof. Offline recovery remains explicitly unconfigured, rather than inventing a backup recipient.

Trade-off accepted by owner: unlike login runtime SOPS secrets, decrypted files persist across reboots. File permissions and encrypted local backups matter. Never export the existing identity or tokens to WSL, the builder or Windows.

### 5. Checks render the actual source and keep the effective assertions

Replace `home.home.activationPackage` with a per-host chezmoi render/apply check generated from `fleet.hosts`. In a sandbox use isolated HOME/XDG config/state, source copied from the tracked checkout including `.chezmoiroot`, non-secret host data and explicit target OS; no init prompts, downloads or production decryptions. Apply ordinary files and modify fixtures without executing live setup; test scripts separately with packaged helper doubles. Assert `chezmoi verify` and repeated-apply no changes. For real production-secret sources, a dedicated `.chezmoiignore` check-mode branch excludes only those paths and a separate synthetic-secret check proves encryption/modes; assert that check mode does not affect ordinary host ownership.

Rewrite `checks/{desktop-batch,air-batch,container-runtime}-config-check.nix` to accept rendered config/profile/manifest and installed user package set. `ssh -G` still asserts identity, stdin, strict checking, no password/keyboard-interactive fallback, interactive defaults, no batch master/ControlPath/persistence and timeout 8. Replace the store-only pin-path shape assertion with exact managed pin contents/fingerprint and strict checking, not weakened `accept-new`; no other known-host source for that endpoint. Check role selection from declared role facts, not `home.programs.ssh`/package existence. Preserve root builder SSH checks (they read system `/etc/ssh`), browser ABI, isolation, font, SCCH, tailnet, host-system and package helper gates unchanged.

Colima checks read the rendered YAML and `.zshenv`: positive resources/mounts, Nix-derived architecture, VZ/Rosetta/virtiofs, Docker runtime, network fields, `autoActivate=true`, `COLIMA_SAVE_CONFIG=false`, `DOCKER_CONTEXT=colima`, immutable smoke-image digests, Colima/Docker/check commands and absence of dockerd. Inspect both system activation and rendered chezmoi scripts for forbidden `colima start` and global socket link; assert no system/user Colima agent. Execute `docker compose version` with no mutable plugin directory. This preserves behavior while discarding HM activation-symlink assertions that no longer apply.

Delete HM imports/state wiring; remove `home-manager`, `sops-nix` and `catppuccin` inputs/lock nodes after callers disappear. Keep `nix-index-database` system modules and `personal-omp-plugin`'s change-1 build-time OpenSpec check input only. Update module-import validation and old comments/paths to the actual new boundaries. Rejected: checking a second hand-built config fixture only (could diverge from templates), executing user scripts against the runner desktop, reducing existing assertions to successful rendering.

## Migration Plan

### Isolated mechanics proof completed during planning

Built pinned chezmoi using `nix build --inputs-from . nixpkgs#chezmoi --no-link --print-out-paths` with temporary HOME/XDG directories. Observed output `/nix/store/mshlva1kqda5a0b2yyzv8xwdf4bl7qzd-chezmoi-2.70.3` and exit 0. A temporary checkout with `.chezmoiroot=home` and a distinct target home held a `.gitconfig` symlink to that immutable store executable plus an app-owned JSON fixture. `apply --force --no-tty` replaced the symlink with a regular rendered file, left the store target SHA-256 unchanged, and the modify filter changed the declared key while preserving an unrelated UI-state object. Subsequent `verify`, `apply`, `verify` all exited 0; another unchanged apply preserved both file mtimes. All spike files and temporary HOME directories were removed. This proves the primitive on Linux, not live Mac cutover or Zed JSONC/Karabiner behavior. Real host-specific adoption still has explicit gates below.

Use `--force` only for the reviewed inventory of already-backed-up HM symlinks; do not blanket-force arbitrary user files. Preview with dry-run/diff, compare symlink targets to the captured HM manifest, and handle unexpected files as a conflict. App-owned files are backed up and merged, not re-added as an opaque snapshot over the template source. If a symlink points to a whole application config, the replacement file is materialized before modification; never mutate the Nix store target.

### Prepare once, then cut over Mac first and WSL second

1. Require archived change 1 and reviewed implementation. Record each host's current system/HM generation and pin both against garbage collection. Capture HM-managed path/symlink manifest and local permission-preserving backups of those destinations plus mutable Zed/Karabiner settings, launchd definitions, relevant Mac preferences and chezmoi config/state if it already exists. Backups stay local outside checkout, 0700; secret/age material is not exported. Record what was absent so rollback removes only cutover-created paths.
1. Implement source/resources/packages/checks; build both systems and run each installed-Nix gate in sequence. Mac additionally runs build-plan guard. Perform Mac-only secret conversion before removing the old SOPS source from the reviewed final tree. Keep old ciphertext in the retained local revision/system generation, not as a permanent compatibility fallback.
1. Obtain explicit owner authorization for any push/merge. Build final reviewed system outputs before live switch. The system switch must not apply user files as root.
1. Mac: agent runs the first system switch in a terminal; owner types the sudo password. Keep a local administrator recovery terminal. Switch installs chezmoi/helpers/resources and removes HM activation/old user agent ownership. As the ordinary user run `chezmoi init --source "$checkout"`, select `macbook-pro`, inspect ordinary diff and secret path/mode metadata without printing decrypted values, then apply the reviewed path set. Later `darwin-switch` runs system switch then user `chezmoi apply` and prints closure diff; nonzero user apply remains a visible partial cutover, not automatic system rollback.
1. Mac: verify fresh login/non-tty shells, `chezmoi verify`, Git/gh identity, SSH effective/live endpoints, private secret consumers, keyboard/layout/default apps/Terminal font, screenshot destination, GUI Nix hook path, Air agent and unchanged Colima lifecycle/profile. Reapply same revision and check unchanged mtimes. Only proceed to WSL after Mac acceptance.
1. WSL: build `nixosConfigurations.korolev.config.system.build.toplevel`, require active user manager, `sudo nixos-rebuild switch --flake .#korolev`, then ordinary-user init with `data.host=korolev` and apply. NOPASSWD sudo is currently observed for this user; if a prompt occurs the owner enters it in the agent terminal. An optional tested `wsl-switch` may wrap these two steps, but documented direct commands remain sufficient.
1. WSL: `chezmoi verify`, fresh Tern WSL login/non-tty shell, Git includes/local overrides, gh HTTPS/GCM/GPG behavior without reenrollment, SSH Mac endpoints and root builder, no leaked Darwin setup/secrets, system unit health, SCCH and Podman smokes. Confirm OMP/plugin writable state unchanged and tools remain visible; installer/plugin behavior is not repeated here.
1. Retain previous generations/backups until all applicable gates pass. Archive only after both live hosts, consumer smokes and rollback evidence pass; owner authorizes publication separately.

### Recovery is two-part, not a Nix-only rollback

On any rejected cutover, stop applying new user changes and keep diagnostic output free of secrets. Restore the previous system generation using README's native Darwin rollback or `nixos-rebuild switch --rollback --no-reexec`. Disable/remove only the new cutover-owned user destinations after backing up post-cutover app edits locally; restore the captured HM symlinks/regular files, permissions, previous user agent/preferences and original app-owned settings. Use the retained HM activation only after conflicting chezmoi-owned replacements have been removed; restore the old chezmoi local config/state or absent state so the rejected source cannot reapply itself. Keep the original age identity and existing GCM state untouched. Restore SOPS consumer availability/agent through the old generation; remove only the new persisted credential copies after old consumers pass. Verify previous shell/Git/SSH/secrets/apps and VM state. No rollback operation deletes OMP state, Colima disks, project repos, keys or provider enrollments.

After the migration is accepted, rollback between chezmoi revisions also requires selecting the corresponding source revision and applying it as the user after system rollback; keep source revisions/resources compatible. File backups, not chezmoi's script ledger alone, restore removed paths/app state/preferences. Never promise transactional all-or-nothing system+user apply.

## Risks / Trade-offs

- Persisted credentials and local backups enlarge the plaintext-at-rest window → private modes, encrypted host storage/backups, no secret diff in transcripts and explicit operator acknowledgement.
- `run_onchange_` does not detect drift of external preferences on an unchanged source → helper checks, consumer smokes and explicit selected-script recovery; no second scheduler.
- Nix generation GC can break rollback resource/symlink targets → pin both original system and HM generation until acceptance and retain local manifest/backups.
- JSONC/settings or Karabiner profile schema differences → parse-controlled fixtures and actual app verification; fail without replacing malformed files.
- Two-step apply can leave packages updated but user files unapplied → report phase failure and recover both owners deliberately.
- Mac GUI dialogs, login-only changes and Secretive hardware authorization cannot be proven in sandbox → owner-assisted actual application checks; no fabricated acceptance.
- Air may be unavailable → static checks still pass, but its existing live integration acceptance is recorded blocked rather than silently dropped; do not turn it into a durable fleet dependency.
- Shared TOML schema evolves when Windows arrives → platform-qualified paths/users from the start and one data.host identity; change 3 adds Windows only after this contract is archived.
