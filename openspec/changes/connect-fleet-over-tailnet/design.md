## Context

See `proposal.md` for the motivation. This change starts after `declare-typed-host-options` is archived, so `options.host` exists in `modules/fleet/host.nix`, each host declares itself in `hosts/<name>/`, and user-scope modules read `osConfig.host`.

Measured on 2026-09-04 from `korolev`:

- WSL runs in NAT mode. `eth0` is `172.29.187.101/20`, `/etc/resolv.conf` is generated by WSL and names `10.255.255.254`, the DNS-tunneling address of the Windows host. `getent ahosts macbook-pro.local` returns nothing. Windows itself resolves `macbook-pro.local` to `192.168.0.163` by mDNS. TCP 22 on the Mac is closed: Remote Login is off.
- `flake.nix:429-434` (`korolevIsolation`) asserts no `sshd`, no open TCP port, and no `sops` for `korolev`, and its comment records the reason: the machine runs endpoint data-loss prevention.
- `modules/darwin/nix.nix:35-38` lists `glockyco` in `trusted-users` "to use the Numtide substituter". That rationale is wrong: daemon-declared substituters serve every client. A remote builder needs it for a different reason, because the build client imports unsigned store paths as that user.
- `modules/home/darwin/ssh.nix:11-14` and `modules/home/darwin/network-shares.nix:9-11` spell `MacBook-Air-von-ISYS.local`; `network-shares.nix:18` probes port 445 on that name before mounting; `packages/air-batch-config-check.nix:21` and `packages/air-batch-check-tests.nix:26` assert the same literal.
- The Air is borrowed for a few more months. Its only purpose is access to PhD thesis and TOSEM paper results. It must leave the topology without changing any durable fleet capability.

Verified in the pinned inputs:

- nixpkgs ships `tailscale` 1.98.10. The NixOS module offers `extraUpFlags`, `extraSetFlags` (implemented as a `tailscaled-set` oneshot, `tailscale.nix:237-248`), `openFirewall`, `disableTaildrop`, and `authKeyFile`. The nix-darwin module offers `enable`, `package`, and `overrideLocalDns` only, and runs `tailscaled` as `launchd.daemons.tailscaled` (`services/tailscale.nix:54-59`). `tailscale set --help` does not list `--advertise-tags`, and `tailscale set --advertise-tags=tag:macbook-pro` exits 2. Tags therefore belong only to the authenticated `tailscale up` command.
- `nixos-wsl` exposes `wsl.wslConf.network.generateResolvConf`.
- Tailscale documents that its SSH server runs on Linux and on macOS only with the open-source `tailscaled` variant, that a tagged node has no key expiry, that SSH rules from a tagged source cannot use check mode, that the control plane distributes SSH host keys, and that the GitOps action accepts a federated identity (`oauth-client-id` plus `audience`) with the `policy_file` scope. The GitOps documentation warns that a policy file may contain e-mail addresses and must then live in a private repository.
- `gh repo view glockyco/nix-config` reports `PUBLIC`, and the repository has no Actions secrets.

## Goals / Non-Goals

**Goals:**

- Every durable host and declared temporary peer has a stable name and a private path to each policy-permitted destination.
- `korolev` is reachable by no other node, holds no SSH private key, and can build `aarch64-darwin` derivations on the Mac.
- The access policy is repository data with evaluated invariants, tested by Tailscale at every apply, and applied only from `main`.
- No `.local` name and no LAN address remains in configuration or checks.

**Non-Goals:**

- Tailscale on the Windows work host. Only the `korolev` distribution joins. Intune owns the Windows host.
- Management of the Air or the desktop. Their owners install the Tailscale application by hand. Policy data marks the desktop durable and the borrowed Air temporary.
- Tailscale SSH on the Air. The graphical application cannot serve SSH. The Air keeps Apple's `sshd`, and the Mac keeps its Secure Enclave key for it.
- Subnet routers, exit nodes, Taildrop, session recording, Funnel, and Serve.
- Inbound access to `korolev` of any kind, including from the owner's own devices.

## Decisions

### 1. One tailnet, tagged nodes, MagicDNS names

Each managed host declares `host.tailnet.tag` (`types.strMatching "^tag:[a-z0-9-]+$"`, no default) in `modules/fleet/host.nix`. Unmanaged peers are data in `modules/shared/tailnet-peers.nix`. Each peer declares `tag`, `lifecycle = "durable" | "temporary"`, and a non-empty `purpose`. The desktop is durable. The Air is temporary and states that it exposes research results until the borrowed machine is returned. Node names equal host names, so MagicDNS yields `macbook-pro`, `korolev`, `air`, and `desktop` while all four are declared.

Tags rather than user-owned nodes: tags are the stable policy subjects that keep e-mail addresses out of the public repository. Tagged nodes do not expire automatically. That property is required for the unattended builder and accepted temporarily for the Air. The Air's explicit offboarding revokes the node before the machine is returned. `tagOwners` maps every declared tag to `autogroup:admin`.

Alternative rejected: user-owned nodes with expiry disabled per device in the admin console. That state lives outside the repository and is invisible to review.

### 2. Policy rendered from Nix data and applied through GitOps

`packages/tailnet-policy.nix` renders `policy.hujson` (JSON is valid HuJSON) from the host declarations and the peer data:

```text
tagOwners  every declared tag -> [ "autogroup:admin" ]
grants     src ["*"]           dst [tag:macbook-pro tag:air tag:desktop] ip ["*"]
ssh        src [tag:korolev]   dst [tag:macbook-pro] users [glockyco] action accept
           src [autogroup:member] dst [tag:macbook-pro] users [glockyco] action check
tests      each non-korolev tag: deny TCP tag:korolev:22
sshTests   tag:korolev -> tag:macbook-pro accept as glockyco
           tag:macbook-pro -> tag:korolev deny
```

The `dst` list is derived: every declared tag except the tag of any host whose declaration sets `host.tailnet.reachable = false`. `korolev` sets it. The renderer asserts that no `dst` in any grant or SSH rule names an unreachable tag, that the rendered text contains no `@`, and that every managed host has a tag. This evaluation assertion covers every port. Tailscale network tests require one numeric port per destination, so the live network tests use TCP port 22 and the SSH tests deny remote login to `korolev`.

`.github/workflows/tailnet-policy.yml` installs Nix with the same action as `check.yml`, runs `nix build .#tailnet-policy`, and calls `tailscale/gitops-acl-action` with `policy-file: result/policy.hujson`: `action: test` on pull requests, `action: apply` on pushes to `main`. Authentication uses a federated identity created in the Tailscale admin console for this repository, so GitHub stores `TS_OAUTH_ID`, `TS_AUDIENCE`, and `TS_TAILNET` as repository secrets and no long-lived token. The admin console setting "Prevent edits in the admin console" is enabled with this repository as the external reference.

Alternatives rejected: a tracked `policy.hujson` edited by hand duplicates the host declarations and can name `korolev` as a destination without any evaluation catching it. An OAuth client secret in GitHub is a long-lived credential where a federated identity needs none.

### 3. Tailscale SSH on the Mac, Apple `sshd` off

`modules/darwin/tailscale.nix` enables `services.tailscale` and adds one launchd daemon, `tailscaled-set`, that runs `tailscale set --ssh` after authentication completes. Its packaged runner waits until `tailscale status --json` reports `BackendState` as `Running`. Command success only proves that the local socket exists, and an initial `tailscale up` resets preferences applied while the state is `NeedsLogin`. launchd retries the runner when `tailscale set` fails. This mirrors the NixOS `tailscaled-set` option boundary while adding the ordering that first-time macOS authentication requires, because nix-darwin has no `extraSetFlags`. The module declares the option `services.tailscale.extraSetFlags` with the NixOS type and description, and one task tracks the upstream nix-darwin pull request that adds the same option. The one-time authenticated `tailscale up --advertise-tags=tag:macbook-pro` command assigns the declared tag because `tailscale set` does not support `--advertise-tags`. When upstream ships compatible authenticated-state ordering, the repository option and runner are deleted while the declaration stays. `services.openssh.enable` stays unset, which leaves Remote Login off.

Tailscale SSH rather than Apple `sshd` with an `authorized_keys` entry: the build client then needs no private key on `korolev`, revocation is a policy edit that takes effect in seconds, host keys are distributed by the control plane, and the Mac's `sshd_config` and `authorized_keys` stay untouched. The cost is that any OS user on `korolev` can open the session. `korolev` is a single-user machine, and the SSH rule limits the remote user to `glockyco`.

Alternative rejected: Apple `sshd` plus a builder key generated on `korolev`. It works and needs no control plane, but it puts an SSH private key on the work machine, which is the one thing the reversed decision still tries to avoid.

### 4. Host keys from the control plane through `KnownHostsCommand`

`packages/tailnet-known-hosts.nix` is a `writeShellApplication` that reads `tailscale status --json`, selects the peer whose DNS name or host name matches `%H`, and prints its `sshHostKeys` in `known_hosts` format. `korolev`'s system `ssh_config` (`programs.ssh.extraConfig`) sets `KnownHostsCommand` to it for `Host macbook-pro`, together with `BatchMode yes`, `ConnectTimeout 8`, `ControlMaster no`, and `ControlPath none`, which are the Air's batch transport rules. `packages/tailnet-known-hosts-tests.nix` drives the program with fixture JSON: a matching peer, a peer without SSH keys, and an unknown name.

Alternative rejected: pin the Mac's Tailscale SSH host key in `programs.ssh.knownHosts`. The key rotates on every `--force-reauth`, and the pinned literal duplicates control-plane state that the peer's authentication already covers.

### 5. `korolev` as remote-build client

`modules/nixos/tailscale.nix` enables `services.tailscale` with `extraSetFlags = [ "--shields-up" ]`, `disableTaildrop = true`, and `openFirewall = false`. The one-time authenticated `tailscale up --advertise-tags=tag:korolev` command assigns the declared tag. `modules/nixos/nix.nix` sets `nix.distributedBuilds = true`, `nix.settings.builders-use-substitutes = true`, and one `nix.buildMachines` entry: `hostName = "macbook-pro"`, `sshUser = "glockyco"`, `system = "aarch64-darwin"`, `protocol = "ssh-ng"`, `maxJobs` and `speedFactor` from the Mac's core count, `supportedFeatures = [ "big-parallel" ]`, no `sshKey`. The entry derives its host name and user from the Mac's host declaration through `inputs.self.darwinConfigurations.macbook-pro.config.host`, so a rename changes it in one place.

`--shields-up` blocks inbound connections on the node itself, in addition to the policy. Direct connections still work when `korolev` initiates them. If the Mac's application firewall drops inbound UDP for the unsigned `tailscaled`, traffic falls back to a DERP relay; the live check records `tailscale ping macbook-pro` so the path is known.

### 6. Declarative DNS on `korolev`

WSL regenerates `/etc/resolv.conf` at every start, which overwrites what `tailscaled` installs for MagicDNS. The host sets `wsl.wslConf.network.generateResolvConf = false`, enables `services.resolved`, and declares `networking.nameservers = [ "10.255.255.254" ]`, the DNS-tunneling address measured on this host. `tailscaled` then adds the MagicDNS split domain through `systemd-resolved`. A task confirms that `korolev` still resolves employer names and that `macbook-pro` resolves to a `100.64.0.0/10` address.

Alternative rejected: a `100.x` address literal for the Mac. It is stable per node, but it is another literal for a fact the control plane owns, and it leaves the resolver under WSL's imperative control.

### 7. The Air is one removable temporary integration

`modules/home/darwin/ssh.nix` sets `HostName = "air"`. `network-shares.nix` mounts `smb://joaichberger@air/Macintosh%20HD` and replaces the mDNS reachability probe with `tailscale status --json` peer state for `air`. The `air-batch` transport rules do not change. `air-batch-config-check.nix` and `air-batch-check-tests.nix` assert the new name. The `Host air` block and the Secure Enclave key remain while the Air serves Apple `sshd`.

No durable build, storage, authentication, activation, or release gate references the Air. The policy renderer has a fixture without the Air and proves that no `tag:air` owner, grant, SSH rule, or test remains. The durable Mac, `korolev`, and desktop topology remains valid.

The offboarding issue records the removal order. First preserve the required research results. Revoke the Tailscale node before returning the machine. Remove the peer declaration and apply policy. Remove the Mac's SSH, batch, SMB, and credential state. Finally remove the `air-client` role introduced by `separate-platform-baseline-from-roles`.

Implementation creates one planning issue titled `Retire borrowed Air after research-result retrieval` with that done-when boundary. The future physical return does not keep this active change open.

### 8. Checks

- `tailnetPolicy`: evaluation assertions from decision 2 plus a `runCommand` that parses the rendered file with `jq` and asserts the `tests` block covers every reachable tag against `korolev`.
- `tailnetPolicyRejects`: evaluates the renderer with fixture data that names `korolev` as a destination and with data that contains an e-mail address, and asserts each rejection through `builtins.tryEval` with `deepSeq`.
- `korolevIsolation` extended: `services.tailscale.enable`, `openFirewall == false`, `disableTaildrop`, `extraSetFlags == [ "--shields-up" ]`, `networking.firewall.allowedUDPPorts == []`, `nix.distributedBuilds`, exactly one build machine named `macbook-pro` with no `sshKey`.
- `macbookProTailnet`: `services.tailscale.enable`, `extraSetFlags == [ "--ssh" ]`, launchd passes only that supported setting, `services.openssh.enable == null`, and `glockyco` remains in `trusted-users`.
- `tailnetKnownHostsCommand`: fixture tests from decision 4.
- Live, packaged as `tailnet-builder-check`: builds a uniquely named derivation containing `uname -m` and `hostname` with `system = "aarch64-darwin"`, asserts `arm64` and `macbook-pro`, then runs `tailscale ping macbook-pro` and prints the path. A per-invocation nonce forces a real remote build because Nix 2.33 cannot apply `--rebuild` check mode to a Darwin derivation from the Linux client. It is the documented acceptance command for this capability.

## Risks / Trade-offs

- [The tailnet control plane is unavailable] → Existing WireGuard sessions continue. New SSH sessions to the Mac fail until it returns. Builds fall back to failure, not to local building, because `aarch64-darwin` cannot build on `korolev`. The Darwin gates on the Mac itself do not depend on the tailnet.
- \[Any `korolev` OS user can open the Mac session\] → Single-user machine, remote user fixed to `glockyco` by policy, and `korolev` runs no service that accepts remote input.
- \[`nix-daemon` absent from the remote non-interactive `PATH`\] → The user's shell is zsh, and nix-darwin's `/etc/zshenv` sets the Nix profile paths. A task measures `ssh macbook-pro 'command -v nix-daemon'` before enabling `distributedBuilds`.
- \[Inbound UDP to the unsigned macOS `tailscaled` is dropped by the application firewall\] → Connections initiated by `korolev` still negotiate a direct path. If measurement shows a relay, the design accepts the relay for build traffic and records the measured throughput.
- \[`10.255.255.254` changes\] → The address is WSL's documented DNS-tunneling endpoint and stable across restarts. The runbook states how to confirm it, and the `korolev` check asserts the declaration matches the running `resolved` upstream.
- [A policy edit in the admin console diverges from the repository] → "Prevent edits" is enabled, and the next `apply` overwrites console edits.
- [The temporary Air tag disables automatic key expiry] → Its declaration is isolated, its purpose is narrow, and offboarding revokes the node before the borrowed machine is returned.
- [Employer endpoint monitoring observes the tailnet client] → Accepted by the owner and recorded in the decision log.

## Migration Plan

1. In the Tailscale admin console: create the tailnet, enable MagicDNS, create the federated identity for this repository with the `policy_file` scope, enable "Prevent edits", and add the three GitHub secrets.
1. Land the policy renderer and the workflow first. Merge applies the policy before any node joins, so no node ever runs under the default allow-all policy.
1. Activate the Mac. Run `tailscale up --advertise-tags=tag:macbook-pro` once with the owner's login, confirm `tailscale status` shows the tag and SSH advertised, and confirm Remote Login is still off.
1. Activate `korolev`. Run `tailscale up --advertise-tags=tag:korolev` once, confirm shields-up and MagicDNS resolution, then run `tailnet-builder-check`.
1. Install the Tailscale application on the temporary Air and durable desktop. Authenticate each with its tag, then confirm `ssh air` and the SMB mount from the Mac.
1. Create the Air-retirement planning issue with the tested offboarding procedure. Confirm that removing the Air from a policy fixture leaves no tag or policy reference.
1. Rollback: `tailscale logout` on a node removes it from the tailnet. A Nix generation rollback removes the client from either host. The policy is reverted by reverting the merge, which the workflow applies.
