# Design

## Context

See `proposal.md` for motivation. This is fleet change 3. It starts once plugin-manager publishing is archived and upstream OMP/Tern and the chezmoi replacement are merged and live on Korolev; their remaining Mac gates do not depend on this change and may close later. Change 3's own Mac steps (enrolling the native Windows key on the Mac and the Mac-source SSH checks) run in the same owner-attended Mac session as change 2's Mac cutover. Current files are migration evidence, not permission to retain Home Manager, wrappers or Zed's OMP agent server; Herdr stays installed on WSL as a secondary tool. Change 4 must wait for native-session and network acceptance here.

Verified repository evidence:

- `packages/windows-configuration/{applications,files,settings,font,powershell,package}.nix` renders the document, two Administrator scripts and sixteen review files. `files.nix` owns native app destinations today, including Windows Terminal's generated NixOS profile, Fork's checksum-pinned wslgit, Zed WSL nixd/TexLab settings, Zen profile assets, PowerToys, ReNeo and AltSnap. The Neo script pins both DLLs and registry identity; the font installer is user-scoped because the available font installer elevates.
- `packages/windows-configuration-check/src/windows_configuration_check/{__init__.py,parse.ps1,winget-configuration.schema.json}` validates metadata/selectors, Intune exclusion, resource names/dependencies, schema, input ordering, privilege exceptions and PowerShell ASTs; its package and `checks/windows-configuration.nix` require Nix. Preserve useful rules, not Python's import/console interface or obsolete output-file counts.
- `AGENTS.md:20`, README Network/Develop/Activate and `docs/operations/wsl-omp-bootstrap.md` still assume inbound Korolev is forbidden, WSL owns Tailscale and the primary worktrees, and Windows output is copied from a Nix build. Those statements must change together.
- `hosts/korolev/host.nix` declares `reachable=false`; `lib/tailnet-policy.nix` already derives all-port grants from reachable tags and port-22 denials from unreachable hosts. Its tests currently have only `deny` targets. `checks/tailnet-policy-{check,rejects}.nix` has synthetic peer/unreachable fixtures worth retaining. `modules/shared/tailnet-peers.nix` keeps desktop durable and Air temporary. The two workflows enforce native Nix checks plus separately authorized policy test/deploy.
- WSL `tailscale.nix` enables shields-up and its authenticated-state helper. `wsl.nix` fixes DNS tunneling at `10.255.255.254`, uses systemd-resolved and NAT; `builders.nix` and `programs.nix` keep the root-only Mac credential and pinned key separate from interactive SSH. Existing `tailnet-builder-check` invokes Linux `tailscale ping`: that diagnostic must move to the native Windows CLI while its nonce-bearing remote-build proof remains.
- The archived layer design records `JGlock` as a standard Intune/Azure AD work account with a separate Administrator credential, and explains why an Administrator apply writes the wrong HKCU/profile. The archived desktop design records the all-profiles OpenSSH firewall rule and the need to disable both password and keyboard-interactive authentication. The archived tailnet design records read-only PR authorization, serialized exact-SHA main deploy, and DNS/build acceptance.
- Owner-approved audit on 2026-10-07: Git 2.55.0.5 is at `%LOCALAPPDATA%\Programs\Git` (HKCU/user PATH). Intune's Git package is Patch My PC's update-only “Update für Git 2.51.0.2”, with HKLM-only detection/requirements in `C:\ProgramData\Microsoft\IntuneManagementExtension\Logs\AppWorkload.log`. Git is therefore not updated by Intune in this scope. Docker Desktop remains excluded. Tern has already run but its executable is in a temporary spike folder. All firewall profiles allow local rules. These are recorded evidence, not new live measurements by this change.
- Read-only native `cmd.exe /c whoami /user` during planning returned `scch\jglock`, an AD-domain principal (not an Entra-only username). Microsoft's [Windows OpenSSH configuration reference](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh-server-configuration) documents lowercase domain account matching, profile authorized_keys for non-administrators, and that Entra authentication is unsupported. It also lists directives absent from the in-box server, including `KbdInteractiveAuthentication`, `StrictModes` and `PermitTunnel`; configure only supported directives and verify key-only effective behavior rather than transplanting the desktop preview server's config.

## Goals / Non-Goals

**Goals:** Native work without Nix in the Windows user environment; one owner per destination; explicit package/version/scope boundaries; one reachable Windows Korolev node while WSL remains service-isolated; native gates and real application/session evidence; reversible credential/node cutover without transferring secrets.

**Non-Goals:** Change Intune policy, join Windows to a different organization, elevate `JGlock`, enable RDP/SMB/WinRM on Korolev, modify desktop account privileges, add a session-persistence service, new package manager, package updater/scheduler, Windows Nix port, mirrored WSL networking, tailnet routing features, native C#/Unity or Nix LSPs, project SDK/build ownership, or copying authentication/private keys. Mac LaTeX is selected; retained WSL TeX packages are secondary CLI tools and are not removed here.

## Decisions

### 1. Capture source once, then remove the renderer completely

At implementation, build the reviewed pre-cutover `.#windows-configuration` once; record revision/output identity and checksums of `configuration.winget`, `apply-zen-policies.ps1`, `apply-kbdneo.ps1` and review assets. Copy the three primary artifacts to `windows/` as ordinary hand-maintained files before changing their resources. Move surviving user configuration into `home/` and shared TOML from change 2; preserve pinned theme licenses/checksums and Neo/font/AltSnap release data. Retain no generated reference mirror as a competing source.

The document keeps settings, package/install resources, schema/processor metadata and per-resource application metadata. `windows/managed-applications.json` preserves the dated exclusion audit (minus per-user Git). It is an exclusion fact, not a second app/pin list. `windows/` also contains native check fixtures and tooling entrypoints. Remove `packages/windows-configuration/`, `packages/windows-configuration-check/`, `checks/windows-configuration.nix`, output/check wiring and related references when replacements exist. The package overlay's directory discovery naturally stops exporting deleted packages; inspect every caller, not just one named export.

Reject keeping a Nix-generated source, because it makes native editing/bootstrap depend on the environment being retired. Reject an entirely new hand-coded configuration engine: WinGet Configuration continues to converge apps/settings, while narrow PowerShell exists only for installers and native validation where needed.

### 2. Separate packages/settings from user files; bootstrap breaks the chezmoi cycle

Keep `.chezmoiroot=home`; native checkout is `C:\Users\JGlock\src\github.com\glockyco\nix-config` with ghq root `~/src`. Extend `hosts.korolev.platforms.windows` in `home/.chezmoidata/hosts.toml`; Linux `user`/home and Windows `JGlock`/home must never be inferred from each other. Reuse `.chezmoi.toml.tmpl` to persist host selection and actual checkout `sourceDir`; reuse portable Git/SSH/shared app defaults instead of cloning templates.

Initial standard-user bootstrap installs per-user Git and `twpayne.chezmoi`, clones the native checkout and initializes chezmoi without applying. Inspect diff first. Native Git sets work email globally, the GitHub no-reply conditional include for `~/src/github.com/`, local override precedence, `ghq.root`, `main`, existing pull/push/LFS/delta policy, `autocrlf=input` (override Git for Windows' observed system `true`) and Windows GCM with Overleaf's generic provider. Private keys, gh `hosts.yml`, GCM vault contents, browser logins and OMP state remain app/user-owned. Record the installed GCM helper relative path in shared host data after verifying it: observed Git \<=2.55 uses `mingw64/bin`, documented >=2.56 moves to `ucrt64/bin` ([GCM WSL docs](https://github.com/git-ecosystem/git-credential-manager/blob/main/docs/wsl.md)); native Git update acceptance must reconcile that path before change 4's WSL helper depends on it. No fallback helper chain.

Package-before-file ordering: a Windows-only `run_onchange_before_` PowerShell script runs the checkout's `windows/configuration.winget`; render a hash of the actual document into it. Use the shared checkout-path fact and verify it agrees with Git's actual repository root, including `.chezmoiroot` semantics; do not guess relative paths from an effective `home/` source directory. Check native command exit codes explicitly. An unchanged apply does not rerun the document; `winget configure test` is the independent drift check and explicit approved rerun repairs external package drift. Initial Neo/Tailscale/SSH prerequisites are completed before ordinary apply where required. An elevated entire `chezmoi apply` is forbidden.

Chez owns Zed JSONC-preserving modify settings, its fully enforced Windows-first keymap and pinned theme; Fork's `GitInstancePath` points at native per-user Git and preserves unrelated settings; Zen profile themes and its one declared user.js preference preserve cookies/history and unrelated preferences. It owns PowerToys declared module keys, ReNeo config/launcher and AltSnap INI values without duplicating installer resources. Move the old stop/write/restart behavior for app-held config to tested chezmoi setup operations; preserve UTF-8 without BOM for JSON/CSS/user.js and preserve AltSnap's original INI encoding/BOM, including UTF-16LE. Apply Zen assets only after a real profile exists; support declared relative/absolute `profiles.ini` paths with controlled fixtures and no profile fabrication. WinGet must stop writing every migrated user destination. Tern settings remain Tern-owned, not a new template.

Reject whole-file overwrite of app-owned settings, elevated user apply, and keeping WinGet user-file resources beside chezmoi: each creates state loss or competing ownership.

### 4. Tern, OMP and annotation remain explicit upstream flows

Install Tern by hand from Stencil's signed-in closed-beta build service into `%LOCALAPPDATA%\Programs\Tern`; verify `tern.exe` there and add that directory once to user PATH with a tested chezmoi user-setup operation. Preserve `%LOCALAPPDATA%\Tern` state. Stop managing Windows Terminal/package/profile; do not uninstall a Windows-supplied terminal or delete unrelated profile state. Remove only the old managed wslgit directory, its declared Fork references and `WSLGIT_DEFAULT_DIST` after native Fork operations pass. No copied wsl.exe masquerading as bash/git remains.

Official OMP installer supports `-Binary` and `-Ref` and defaults to `%LOCALAPPDATA%\omp` ([source](https://github.com/can1357/oh-my-pi/blob/main/scripts/install.ps1)). Use `& ([scriptblock]::Create((irm https://omp.sh/install.ps1))) -Binary -Ref <reviewed-tag>`, an implementation-selected verified released tag; record version/provenance and keep the prior accepted binary until smoke passes. Update with `omp update`, not Bun-global installs. The installer may auto-select bash: inspect actual OMP settings and explicitly select native PowerShell or the Git-for-Windows Bash executable; never accept System32 bash.exe/WSL. Do not manage full OMP config/state through chezmoi.

The install command defined by `publish-plugin-through-omp-plugin-manager` is verbatim `omp plugin marketplace add glockyco/omp-agent-setup`, then `omp plugin install --scope user personal@glockyco`. Upgrade: `omp plugin marketplace update glockyco`, then `omp plugin upgrade --scope user personal@glockyco`, then restart OMP. Commands are `/personal:opsx-*`; no aliases restore bare names. Verify all nine personal skills, personal-policy, both extension modules, LSP overrides/Marksman disabled and the actual plugin version, not just successful install output.

Use Plannotator's Windows installer in minimal mode: `& ([scriptblock]::Create((irm https://plannotator.ai/install.ps1))) -Minimal -Version <reviewed-release> -VerifyAttestation`. [Vendor installation docs](https://docs.plannotator.ai/open-source/start/installation) confirm Windows, minimal mode, release pin and provenance verification. Minimal mode avoids competing vendor-installed skills/hooks with the personal plugin's annotation integration. Provider/GitHub/Stencil logins are owner-assisted interactive operations; no install copies credentials.

**Compatibility risk, not assumed solved:** the plugin companion design `add-plannotator-visual-feedback` excludes native Windows hosting because its listener lifecycle uses POSIX process groups, while the owner reports needed Windows annotation works. Acceptance explicitly invokes `/plannotator-annotate`, `/plannotator-last` and `/plannotator-cancel` natively and checks listener cleanup after cancellation/navigation/shutdown. A failing cleanup blocks this cutover; its real fix belongs in a separately approved `omp-agent-setup` change, never a hidden WSL fallback. Likewise absent-tool LSP filtering is expected upstream behavior, but a selected native server must actually initialize and diagnose representative projects.

### 5. Transfer the node and expose only approved native SSH

Set typed Korolev `tailnet.reachable=true` (the Nix system remains `x86_64-linux`; this flag now describes the Windows-owned machine identity, not a Linux listener). Keep tag, MagicDNS domain, desktop/Air lifecycle and Mac root-builder facts single-source. Remove WSL `tailscale.nix` import/file, stale shields-up assertions, Linux node enrollment instructions and DNS split-domain comments. Leave NAT, resolved and DNS tunneling. Tailscale recommends Windows-only rather than running both clients ([WSL2 documentation](https://tailscale.com/docs/install/windows/wsl2.md)); actual MagicDNS/root-daemon routing is a live acceptance risk, not inferred proof.

Cutover: retain local Windows Administrator recovery and previous Nix generation; record old WSL node ID/tag/name only, not auth keys. Stop/log out WSL Tailscale, revoke its node with owner-assisted console authorization, and activate the reviewed daemon-free WSL generation. Then install/enroll Windows Tailscale with `tag:korolev`, exact hostname and accepted DNS, verify one node/no numeric duplicate, unattended service and durable no-expiry behavior. No Linux state copied to Windows and no permanent pair of nodes. Coordinate short outage. If Windows networking/build gates fail, stop Windows Tailscale before re-enrolling WSL during explicit rollback; never run both to manufacture apparent connectivity.

Generate positive TCP-22 policy tests for reachable source/destination tags and deny tests for unreachable targets. If all real members are reachable, omit empty deny fields; preserve synthetic unreachable fixtures and rejection assertions. All-port `src=["*"]`, `ip=["*"]` grants deliberately give Korolev desktop-like network treatment; OpenSSH keys/firewall control SSH, not a claim that ACLs restrict all services to SSH. Preserve no email/Tailscale SSH rules, peer removal proof, read-only PR identity, exact-SHA deployment freshness and serialized writes. Windows CI belongs in `check`, so `workflow_run` success includes all three platform jobs; update required branch check names with explicit owner authorization. A policy push/merge is separately owner-authorized, never implied by planning or Windows setup.

Tailscale SSH is unsupported on Windows ([reference](https://tailscale.com/docs/features/tailscale-ssh)); use Windows-serviced `OpenSSH.Server~~~~0.0.1.0` via explicit Administrator `Add-WindowsCapability` ([Microsoft first-use guide](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_install_firstuse)). Do not add a third general-purpose elevated script. The runbook owns capability/service/firewall enrollment commands separately from the two fixed scripts and user apply. Set the SSH default shell to the absolute per-user PowerShell ZIP executable. Use the verified AD-domain standard principal `scch\jglock` and its profile `.ssh/authorized_keys`, not the desktop's administrators file; require effective lowercase account matching and a real authentication probe. Mac and desktop retain distinct private source keys and enroll only labeled public keys. Verify NTFS account/SYSTEM ACLs, syntax with `sshd -t` and effective policy with `sshd -T`. Configure supported `AuthenticationMethods publickey` and `PasswordAuthentication no`; reject password and keyboard-interactive attempts by live negative tests. Do not put unsupported in-box directives such as `KbdInteractiveAuthentication`, `StrictModes` or `PermitTunnel` into this server config. Preserve SFTP and disable forwarding using the supported interface; do not add an elevation or tunnel mechanism. Client-side no-password/no-keyboard-interactive settings remain supported independently. Never reuse the root builder key.

Bind sshd to the verified Windows tailnet IPv4 and available IPv6 addresses. Disable installer `OpenSSH-Server-In-TCP` broad allow rule before starting service; add an idempotently named SSH-only firewall rule whose **local address** is exactly the tailnet address(es), with the intended executable/port/profile/source policy. Audit effective broad rules/Tailscale rules so another allow cannot defeat non-tailnet restriction; do not broadly rewrite employer-owned rules. If an employer rule defeats the boundary and cannot be changed with authorization, deployment is blocked. Unavailable/stale address causes a closed listener, not wildcard fallback. Service restart after reboot/re-enrollment and address changes require verification/reconciliation of owned settings. No RDP/SMB service enablement, ports, WSL proxy or LAN fallback.

Reuse change 2's SSH templates for native `desktop`, `desktop-batch`, `macbook-pro`, `macbook-pro-batch` and pins; Windows-specific transport skips unsupported multiplexing but batch stdin/timeout/no-PTY/no-persistence rules remain. Native Windows generates its own approved user key for Mac/desktop; do not copy WSL's user key or builder key. Enroll the new public key on the Mac with its existing PTY-permitted/no-forwarding restrictions (agent runs activation in a terminal, owner types sudo password) and desktop through approved native privileged session. Add Mac/desktop client endpoints/pin for incoming Korolev after console verification. Air is not a new incoming Korolev credential or dependency.

WSL acceptance after moving the tunnel: `getent ahosts macbook-pro.tail8768af.ts.net`, public DNS, applicable employer DNS, `resolvectl status`, root `ssh macbook-pro 'exit 23'`, a fresh nonce-bearing `tailnet-builder-check` and all-system checks. Adapt that check's path diagnostic to Windows `tailscale.exe ping` with quoted native executable discovery; this is the documented network transport, not a fallback for a native agent tool. Repeat after owner-coordinated WSL termination/restart. Retain keys/root perms and no externally reachable WSL service.

### 6. Native quality gates without a second formatter policy

Move existing `treefmt.nix` formatter identities/patterns/exclusions/options to one platform-neutral `formatting.json`; Nix treefmt adapter and a small native PowerShell dispatcher consume it. Preserve ruff format/check, mdformat with GFM/frontmatter, jsonfmt, yamlfmt retain-line-breaks, DNS-only Prettier, Nixfmt and `.omp/**`/encrypted-source exclusions as established by changes 1/2. Tool paths/version distribution are platform adapters, never separate file-pattern lists. Bootstrap native counterparts at versions matching the pinned selected tool records; check checksums/integrities. Missing required native artifact fails bootstrap, not a change of formatter or skip. Unit fixtures prove cross-adapter file selection/options and failures; fixture gates do not rewrite tracked source.

Use lefthook per-platform `skip: run:` jobs ([supported configuration](https://lefthook.dev/configuration/skip/)); skip only because the job is for the other OS. The Windows command dispatches native formatting and Windows invariant tests. It enumerates staged paths itself (safe Git NUL output; paths with spaces supported). For any staged `.nix`, it must execute the pinned Nix gate on the **same native checkout** through the declared Nix environment (WSL if available) or fail clearly; it cannot validate the separately cloned Linux tree, skip, or accept arbitrary PATH Nix. A missing Windows environment likewise fails. Nix jobs retain host-installed implementation gates and `nix develop` hook installation. Native bootstrap installs the same lefthook hook in the Windows checkout; actual Fork commits exercise it.

`check.yml` gains a required Windows job invoking the native bootstrap, shared applicable formatting, Windows PowerShell 5.1 and PowerShell 7 parser tests, fixture-based invariants, pinned official DSC configuration-document JSON Schema validation and `winget configure show --file windows/configuration.winget` as a read-only WinGet parse gate. Provision only runner test dependencies at recorded versions; missing WinGet/DSC fails rather than skipping. The schema checker supports the pinned schema's validation vocabulary in both PowerShell hosts and rejects unsupported validation keywords instead of skipping them. Validation applies no configuration, installs no workstation app and requires no login or enrollment. Linux/Darwin jobs retain Nix gates; Windows full-tree CI delegates Nix files to those jobs, while native commits refuse staged Nix without checking that checkout. Add no Windows host to the Nix registry.

After capturing the rendered YAML, normalize it to JSON-compatible YAML under the same `.winget` name and prove parsed-value equality before migrating resources. Vendor the declared official `2023/08` configuration-document schema and reference closure from DSC `v3.2.3`, retaining source URLs/SHA-256 values and an equivalent locally bundled validation schema. Final declarations use its alphanumeric/space resource names and typed `resourceId()` dependencies. Native checks validate that schema, a resource-type allowlist grounded in actual `dsc resource list` discovery, ASTs for all shipped/rendered PowerShell scripts, app policies/selectors, Intune exclusion, unique names/dependencies, machine exceptions, Neo ordering and forbidden CloudStore/taskbar/default-association claims. Administrator boundaries use parsed variables/strings and controlled fixtures, never source substring checks. Tests use isolated HOME/profile/app trees and doubles; never CI apply. Preserve chezmoi JSONC/profile state and effective SSH pin/batch semantics; findings name resources/scripts and return nonzero.

`winget configure validate` is not the gate: WinGet `1.29.380` returns `1` for both the untouched renderer output and its value-equivalent normalized copy, warning that native DSC v3 resources lack a public module even though DSC discovers them. [Upstream `ValidateConfigurationSetUnitProcessors`](https://github.com/microsoft/winget-cli/blob/master/src/AppInstallerCLICore/Workflows/ConfigurationFlow.cpp) marks module/public-availability warnings as `foundIssue` and terminates with `S_FALSE`. Do not suppress that warning or reinterpret exit `1` as success. Use the official-schema/native-invariant gate and successful read-only WinGet show instead; record processor/resource versions and outputs in implementation evidence.

Reject skipping hooks on Windows, maintaining a second formatter list, copying Linux build artifacts as native evidence, or running live apply in CI.

1. Preserve newly created repositories, app profiles, credentials, OMP history and unrelated settings. Select previous accepted OMP/plugin versions through upstream supported flows. ## Risks / Trade-offs

- Windows-only Tailscale may not pass root-daemon MagicDNS/build routing on this NAT/resolved setup → live restart/build proof blocks acceptance; no duplicate daemon or guessed resolver fallback.
- Intune may change ownership, prohibit capability install or override effective firewall rules → re-audit change-owned scope before deployment; require employer-compatible authorization and stop rather than disable policy/security.
- Native plugin annotation lifecycle currently has a POSIX-only design → explicit command/cancel/cleanup gates; separate plugin fix if needed, no WSL workaround.
- Tern is closed beta → signed-in owner download, stable PATH, actual application verification and previous accepted build retained locally; no invented download URL or package-manager identity.
- All-port reachable-tag grant intentionally increases machine exposure → effective host service/firewall inventory and only approved SSH deployment; do not describe this as SSH-only tailnet policy.
- User ZIP tools and npm wrappers vary across releases → checksum/version/actual process smoke and paths-with-spaces tests; no machine-install fallback.
- GCM path moves across Git releases → record observed helper in shared TOML and recheck WSL helper after native updates before change 4.
- Configuration/user apply/network changes are not transactional → explicit backups and two-part/local recovery; retain prior generations until all applicable gates pass.
- Native formatter counterpart availability/version mismatch → fail pinned bootstrap and resolve packaging within this change, never silently substitute a formatter or bypass staged Nix.
